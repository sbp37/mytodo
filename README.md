# mytodo — 의뢰서 마감 트래커 (기획안)

시즌 FG 개발의뢰서를 **마감 안에, 짧고 굵게** 끝내기 위한 개인용 기능.
이 저장소는 기획 문서만 둔다. **실제 구현은 `sbp37/my-todo`(subin-assistant 사이트)** 에 한다.

---

## 0. 확정 사항

| 항목 | 결정 |
|---|---|
| 위치 | `https://subin-assistant.vercel.app` (저장소 `sbp37/my-todo`, 소스 `subin-assistant-site/`) 안에 **상단 🎯 아이콘 버튼**으로 숨겨서 연다 |
| 기기 | 맥 + 폰. 데이터는 기존 Supabase 프로젝트(`ctthdtsbjjqovtmhrzzj`)에 저장해 동기화 |
| 근무일 | 월~금, 주말 제외. **마감일 당일은 작업일 아님** |
| 검수 여유일 | **1영업일** (설정에서 변경 가능) |
| 27SS 마감 | 2026-11-03 → 검수일 11/2 → **제작 마감 10/30(금)**. 10/14 기준 제작일 13일 |
| 이미지 | `.ai`는 서버/깃에 올리지 않는다. 브라우저에서 첫 페이지를 JPG(~150KB)로 렌더링해 **썸네일만** Supabase Storage에 저장 |
| 기존 코드 충돌 | Devin이 `devin/*-subin-cells` 브랜치에서 레이아웃 작업 중 → 트래커는 `tracker.js` / `tracker.css` 별도 파일 + 헤더 아이콘 1개만 추가 |

### 의뢰서 파일 특징 (샘플 `27SS_7PLOVELY_TYRW270704.ai` 확인)
- Illustrator 30.8, PDF 호환 저장(`%PDF-1.6`), 1페이지, A4 가로, 약 6MB → pdf.js로 렌더링 가능
- 글자가 전부 아웃라인 처리되어 **텍스트 추출 불가** → 정보는 파일명에서만 뽑는다
- **미완료 = 왼쪽 칸에 노란 헤더의 "FG 개발의뢰서" 표가 붙어 있음, 오른쪽은 단색 컬러칩 판**
- **완료 = 의뢰서 표 없이 최종 그래픽이 들어감**
- → 아이디어: 렌더링한 이미지 왼쪽 상단에 의뢰서 노란 헤더색이 있는지 보고 완료 여부를 **자동 추정**, 사용자가 확인/수정

## 1. 해결하려는 문제

- 할 일이 많으면 뭐부터 할지 몰라 헤매다가 막판에 몰아서 끝냄
- 한 건 잡으면 오래 붙잡음 — 짧게 집중하는 게 어려움
- 파일명만으로는 어떤 의뢰서인지 헷갈림 → **이미지로 보고 골라야 함**

## 2. 화면

### ① 오늘 (기본 화면)
- **"지금 이거부터"** 카드를 크게: 의뢰서 썸네일 + 추천 이유 한 줄 + [집중 시작]
- 오늘 목표 = **이월분 + 오늘 몫**을 분리 표시 (예: "밀린 2 + 오늘 6")
- 오늘 할 일 목록(썸네일), "다음 하나만" 버튼
- 오늘 집중 가능 시간 입력 → 추천량이 넘치면 과부하 경고

### ② 시즌
- D-day, 남은 제작일, 전체/완료/남음, 필요한 하루 평균
- 컨셉별 게이지 + `완료/전체` + % + 위험 상태
- 의뢰서 갤러리: 컨셉 탭 → 품목 코드별 묶음 → 썸네일 카드
- `.ai` 여러 개 / 폴더 드래그로 일괄 등록, 카드에 최종본 드래그하면 썸네일 교체
- 스크린샷 붙여넣기(⌘V)로도 썸네일 지정 가능 (PDF 호환 꺼진 파일 대비)

### ③ 기록
- 날짜·시즌·컨셉별 완료 목록, 집중 세션 기록, 하루 점수 히스토리, 예상 vs 실제 시간

### ④ 설정
- 시즌/마감일/검수 여유일, 휴무일, 품목 코드 → 한글 이름, 난이도별 기준 시간, 보상 목록, JSON 백업

## 3. 계산 규칙

- 남은 개수 = 목표 − 완료
- 제작 가능일 = 오늘(작업일이면 포함) ~ (마감일 − 검수 여유일) 사이의 평일 − 휴무일
- **하루 필요량 = ceil(남은 개수 ÷ 제작 가능일)**, 완료/목표 변경/날짜 변경 시 즉시 재계산
- 하루 마무리 시: 오늘 목표 대비 미달분 = 이월, 다음 작업일 필요량을 다시 계산해서 "오늘 2개 미달 → 하루 6 → 7"처럼 원인과 함께 표시
- 마감 초과, 전부 완료, 기록 없음 상태도 안전하게 처리

### 우선순위 (단순 규칙 + 이유 표시, 수동 순서 변경 가능)
1. 이월된 의뢰서
2. 진행률이 가장 뒤처진 컨셉
3. 같은 품목 코드끼리 연달아 (작업 전환 비용 절감)
4. 사용자가 중요 표시한 것

## 4. 집중 타이머 & 점수

- 타이머는 시작 타임스탬프 기반 → 새로고침/폰 전환해도 유지. 일시정지 시간은 집중 시간에서 제외
- 한 의뢰서를 여러 세션에 나눠도 세션별 기록 + 누적 시간 보존
- 타이머 종료 ≠ 자동 완료. 완료는 사용자가 누름
- 완료 시 기록: `14:05 ~ 14:17 · 집중 12분`
- **최종 산출물(의뢰서 1건)** 만 진행률 +1. **세부 미션**(컬러 수정 등)은 체크만, 개수에 안 들어감
- 완료 되돌리기 시 진행률·점수 정확히 복구, 하루 마무리 중복 실행 시 점수 중복 없음

### 점수 — 이중 구조
- **하루 성적 100점 만점**: 계획 달성률 60 + 집중 세션 성공률 25 + 빠른 완료 15
- **누적 포인트(보상 상점용)**: 완료 +10, 난이도별 기준 시간 이내 완료 +30(빡집중) / 2배 이내 +15 / 3배 이내 +5, 하루 목표 달성 +50, 연속 달성 streak 보너스
- 난이도 S/M/L 기준 시간 기본값 10 / 15 / 25분 (설정에서 변경)
- 같은 의뢰서를 쪼개서 보너스 반복 획득 불가
- 배지: 3연속 집중 성공, 오늘 목표 100%, 이월 전부 해결, 위험 컨셉 정상화

### 하루 마무리 리포트 예시
```
오늘의 업무 점수 82 / 100      누적 포인트 +135
목표 5 · 완료 3 · 달성률 60%
집중 2시간 35분 · 세션 6회 · 빡집중 2건
→ 2개 이월. 다음 작업일 목표 6 → 7개
→ 현재 속도면 예상 완료일 11/2 (검수일과 겹침)
```
문구는 죄책감 대신 다음 행동이 명확해지게.

## 5. 데이터 (Supabase)

- 테이블(안): `tracker_seasons`, `tracker_concepts`, `tracker_items`(의뢰서 1건), `tracker_missions`, `tracker_sessions`(집중 세션), `tracker_days`(하루 마무리 스냅샷), `tracker_rewards`
- Storage 버킷: `tracker-thumbs` (비공개, JPG 썸네일만)
- 기존 `assistant-api` 엣지 함수에 `resource=tracker*` / `action=tracker_*` 추가, 인증은 기존 `x-assistant-key`
- 회사 디자인 원본(.ai), 썸네일을 GitHub에 커밋하지 않는다

## 6. 만드는 순서

1. **바로 쓰기**: 🎯 버튼, 시즌·컨셉 등록, `.ai` 드래그 → 썸네일 + 파일명 자동 분류 + 완료 자동 추정, 컨셉 게이지, 하루 목표(이월 분리), "지금 이거부터", 타이머, 완료 기록
2. 하루 마무리 리포트, 100점 성적 + 누적 포인트, 배지, 완료 되돌리기
3. 기록 화면, 예상 vs 실제 통계, 과부하 경고, 보상 상점
